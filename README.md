# 字港 Font Harbor

Windows 本机字体管理器，支持：

- 扫描系统级和当前用户字体
- 批量标签与搜索
- 自定义文字、字号和字符表预览
- 删除前自动备份，保存注册表来源清单
- 从备份一键恢复字体
- Illustrator 检查发现缺失字体时，自动在当前备份目录中匹配，并可勾选安装
- 保护常见 Windows 核心界面字体

## 构建

```powershell
dotnet build -c Release
dotnet publish -c Release -r win-x64 --self-contained true
```

发布文件位于 `bin\Release\net8.0-windows\win-x64\publish\FontHarbor.exe`。

## 新版工作台

- 已安装字体列表：搜索、自定义文字/字号预览、分类筛选，每行“应用”至 Illustrator。
- 完整模式：已安装字体、文件夹预览、Illustrator 检查和备份恢复统一在顶部切换。
- 精简模式：左侧显示已有字体分类和数量，点击即可筛选；隐藏来源导航和重复的分类下拉框。
- 切换完整/精简模式保留当前分类，分类与搜索可组合筛选；窗口置顶和模式自动记忆。
- 备份 / 文件夹预览：扫描当前备份目录，或添加任意文件夹（含子目录），记住来源；支持取消、重扫、搜索、真实文件样张。
- 支持 TTF、OTF、TTC、OTC；损坏文件及无权限目录计数提示，跳过目录链接以避免循环。
- 未安装字体可直接预览；“安装并应用”复制到当前用户字体目录并注册，不改变原始文件。
- TTC/OTC 集合预览真实样式；已安装集合应用时可选择具体字体与样式，保留集合删除保护。

通常直接启动即可，无需管理员权限。只有系统字体删除/恢复需要右键“以管理员身份运行”；请在删除前关闭使用这些字体的应用。

### Illustrator 使用

先在 Illustrator 打开文档并选中文字对象或文字范围，再在字港中点击“应用”。支持选中组中的文字。仅使用精确匹配的字体/样式；不自动保存文档。安装新字体后，如果 Illustrator 尚未识别，重启 Illustrator 后重试。两程序须使用相同权限级别；日常使用建议都以普通权限启动。

此环境未运行 Illustrator：桥接代码与脚本模拟检查已完成，实际版本兼容性仍需在运行中的 Illustrator 文档验证。

## V4 / 1.2.0：真实 API 字体标注

完整模式为左侧分类与标签、中间字体列表、右侧详情三栏。界面按钮、导航和标题采用常规字重；字体样张保留字体本身的字重。选择操作、锁定分类、加入分类和备份删除统一在列表底部。

分类、基础类型、进阶风格可组合筛选：同组多选取并集，跨组与搜索取交集。左栏对当前字体来源显示数量。右栏可以人工修正类型和风格；已有自定义分类和旧标签保留。

### API 配置

1. 打开“API 设置”，填写 OpenAI 兼容接口的 HTTPS 基地址，一般以 `/v1` 结尾；本机模型服务允许使用 loopback HTTP。
2. 填写 API Key；可选“记住密钥”，将使用 Windows 当前用户的 DPAPI 加密保存。未勾选时密钥只留在当前程序内存。
3. 获取模型列表并选择模型，或直接填写模型 ID。模型列表使用 `GET /models`，测试和标注使用 `POST /chat/completions`。
4. 可以在设置页测试模型和视觉能力，也可直接开始自动标注，由程序自动进行视觉验证。视觉测试让模型读取随机数字图片，只有读对才上传字体样张；配置变更和重新启动后会自动重新验证。
5. 打开“AI 标注”，选择已安装字体、备份目录或任意文件夹，查看目标服务并点击“开始自动标注”，程序自动扫描、生成与预览样张、上传识别并保存。默认跳过已标注字体；勾选“只处理选中字体”时可以重新标注。

样张省略目标字体不支持的字符，避免使用系统替代字形误判。API 请求只包含字体名称和固定 PNG 样张，不上传字体文件、字体路径或自定义预览文字。调用可能产生服务商费用。程序不记录密钥或服务端原始错误内容；不自动跟随重定向。

标签保存在 `%APPDATA%\FontHarbor\settings.json`。以文件内容哈希与字体/样式识别相同字体，复用已有结果；手动修改的标签默认不被重扫覆盖。取消任务保留已保存标签；401/403/404 或连续三个失败会停止任务。429/503 最多自动重试两次。

基础类型：衬线、无衬线、等宽、其他/待确认。风格支持手写、书法、卡通、哥特、复古、科技、圆润、装饰。模型输出经过 JSON 和标签值校验，不直接执行模型返回内容。

已完成：1394 条本机注册字体扫描、组合筛选和常规字重渲染验证；API 请求格式、鉴权、视觉校验、错误、重试、取消、密钥加密测试；本机 HTTP 服务端到端标注和取消保留结果。未提供供应商凭据，尚未验证用户选定的外部模型服务。

### 1.2.2 双维标签修复

每个结果必须包含一个基础类型和 1–3 个风格标签，风格不再允许空数组。普通字体可识别为简约、现代、经典、正式等；不确定时明确标为“待确认”，不会伪造风格。无效结果会重新请求一次；仍无效则计入失败。

旧的空风格结果自动显示“待确认”，默认自动任务会再次纳入补全，不再当作完整标签跳过。人工保存也需要填写两个维度。列表以“类型：… · 风格：…”明确区分；旧的人工基础类型在补全风格时保留。

## 1.3.0 分组标签

按 V5 原型实现七组 34 个风格：通用气质、情绪感受、年代与文化、书写风格、趣味装饰、科技与工业、形态与力度。左右栏均可折叠，左栏提供展开/收起全部；风格跨所有分组合计选择 1–3 个，不要求每组都选。

基础类型更新为衬线、无衬线、手写/书法、装饰/展示、其他/待确认。等宽独立为可选字体属性，可与衬线/无衬线共存；AI 标注时由实际字形宽度推断，可人工修正。待确认是状态，不再混入风格枚举。新增属性、完整/待确认状态筛选；同一风格维度内多选取并集，与其他维度取交集。

兼容旧标签：经典映射为古典，哥特映射为哥特式；旧“手写/书法”标签保留原文并标为待确认，等宽基础类型迁为等宽属性并待补基础类型。原始旧标签保存在 LegacyStyles，迁移不改动字体文件或分类，不伪造识别时间。原来的空风格/待确认记录仍会补扫。

AI 提示词按七组约束，要求只能返回 34 个候选中的 1–3 个风格；确实无法判断时返回 needs_review=true，允许空 styles，但不算完整。禁止将待确认当成风格，也不因名称带 Gothic 就归类为哥特式。

### 1.3.1 一键自动标注

移除“准备字体样张”按钮。选择来源/范围后，点击一次“开始自动标注”，程序先扫描并跳过完整记录；有待处理字体时自动验证尚未通过测试的模型，再逐款生成样张、同步预览、上传识别并保存结果。无须逐款确认或上传。

扫描阶段、视觉测试阶段和上传阶段都可以取消；完成结果保留。没有字体或标签均完整时不产生 API 请求。任务运行期间锁定来源与范围，防止重复点击或切换导致混淆。预览图与实际上传 PNG 使用同一份数据。

## 1.3.13 精简模式应用按钮与左栏层级
